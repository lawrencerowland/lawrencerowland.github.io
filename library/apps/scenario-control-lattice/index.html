    What you’re looking at

    This page shows a concept lattice built using Formal Concept Analysis (FCA). FCA does one very specific (and very useful) thing: it finds all groups paired with every attribute common to them, and every scenario having those attributes. The scenarios may have different additional attributes; their complete rows need not be identical.

    Concept = (Extent, Intent)
    • Extent: which scenarios fall into that group
    • Intent: which barriers/evidence tags are shared by all those scenarios

    The “causal” part is in how we write the risks: each scenario has a causal chain (“what starts it → what happens → impact”). Control tags describe proposed ways to interrupt the chain. Evidence tags name records such as walkthroughs, logs, audits or tickets. The matrix alone does not show what a record proves, whether a control was implemented, or whether it was effective.

    What FCA is doing (and not doing)
    • Not inferring causality.
    • Yes surfacing coverage patterns: “Which causal scenarios share the common control attributes?”
    • Yes exposing gaps: “Which scenarios have no control tags (or only evidence tags)?”

    Director‑level questions this view answers quickly: “Which scenarios share a training tag?”, “Which records need a closer look?”, “Which scenarios have evidence tags but no control tags?”, and “Which rows are empty?” These suggest questions, not findings about actual risk.

    How to read nodes

    Each node label shows counts. Example:

    2 scenario(s)
    barriers: 1
    evidence tags: 0
    • Click a node → right panel shows the full intent (shared barriers/evidence tags) and extent (scenarios).
    • Edges connect “more general” to “more specific”: along a downward arrow in Hierarchy view, you add shared attributes and shrink the scenario set.
    • The lattice is deterministic: given the same input matrix, you get the same structure every time.
    Tip: start with general nodes (many scenarios), then follow edges downward until you find small nodes that represent more specific attribute bundles. In Force view, positions have no hierarchical meaning; follow arrow directions. These groupings do not establish weak coverage or a single point of failure.
    What counts as a gap?

    Here a row with a control tag is tagged with a control; it is not thereby effectively controlled.

    Gap rules in this demo
    • No‑barrier gap: scenario has zero control: attributes
    • Evidence‑only gap: scenario has evidence tags (evidence:) but still no barrier
    • No attributes recorded: scenario has no attributes recorded (no conclusion about why)

    Real programs often require both barriers and proof. This demo separates “evidence tag present” from “control tag present” so readers can ask whether a tag is missing, an assessment is incomplete, or a corrective action is needed. The table does not infer ownership or effectiveness.
